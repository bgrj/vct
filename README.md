# 视频截图工具

一个本地运行的视频截图工具，提供两种截图模式：

- **台词智能截图**（默认，新增）：读取视频的**内嵌软字幕**，为每一句台词自动挑选最优画面并落盘，图片底部带该句台词文字。
- **均匀截图**（原有功能）：在视频时长内均匀取帧，批量输出。

关于联网：**视频处理这一步完全在本机完成**——字幕来自视频自带字幕轨，画面评分与人脸分析都在本机 CPU 上推理，视频与图片不会上传。
需要联网的只有两处：① 首次安装（下载 Python / FFmpeg / 依赖包）；② 使用 AI 助手（CodeBuddy 等）下达指令与查看结果。
若只用命令行或 `.bat` 脚本运行，日常使用可以完全不联网。

> 首次使用（如何装环境、怎么建文件夹、怎么给 Agent 下指令、怎么跑、怎么验收）请看同目录的
> **《本地视频自动化截图工具使用指南.md》**；该指南也给出了「先用 AI 助手联网跑通 → 再改成离线一键运行」的两阶段路线。本文件偏参数与实现说明。

## 功能特点

### 台词智能截图

- 自动识别视频中的中文字幕轨（优先「简体中文」），按字幕时间轴精确定位每句台词，无 OCR、无识别误差
- 每句台词在其时间区间内采样多张候选画面（默认 5~10 张，密度 3 帧/秒），挑出最优的一张
- 评分综合：画面清晰度、运动幅度、人像自然度（**眼睛状态**、说话状态、人脸面积）
- **以眼睛为主的神态判定**（眼睛比嘴型更容易被一眼看出问题）：
  - 左右眼分别算开合比（EAR），做「绝对标定 + 句内相对标定 + 双眼是否对称睁开」三重比较
  - 闭眼重罚、半闭眼轻罚、单眼微闭（眨眼瞬间）轻罚；嘴部只保留「张口过大」一层惩罚，权重低于眼睛
  - 选优时先取本句最高分，再在「最高分 - 0.15」的优选窗口内优先挑选**睁着眼**的一帧，兼顾画质与神态
  - 出图帧的眼睛状态（睁开 / 半闭 / 闭合 / 无人像）写入索引表并计入报告统计
- 情境匹配加分：构图更居中、更贴近句子中点、与句子中点同一镜头的候选帧优先，减少「画面与台词对不上」
- 主动避开眨眼、半闭眼、大张口与嘴部扭曲等不自然瞬间
- **闭眼帧重采样**：整句候选都没睁眼时，自动把该句候选帧数与采样密度临时提高（默认 30 帧 / 6 帧每秒）再挑一次，确认「眼睛状态确实变好」才替换图片；每集通常只有个位数句子触发，耗时增量可忽略
- 无人像的空镜、背影、远景、字幕卡（哪怕全黑只剩底部台词）同样正常出图，仅在索引表中标记为降级
- 台词以**白色粗体 + 黑色描边（无底色）**贴在画面底部，字号、描边宽度与贴底位置取自参考素材统计出的样式基线 `style_profile.json`
- 有序命名（含集号、句序、时间码），并按时间顺序排列
- 每集输出 `_index.csv`（台词索引表）与 `_report.txt`（处理报告）
- 收尾做完整性校验：字幕句数 / 目录图片数 / 索引行数三方对齐，缺图的句子自动补跑
- 断点续跑：已生成的图片自动跳过，中断后重跑不重复劳动
- 重建模式（`--clean` 或界面勾选）：先清空该集历史图片与旧索引再生成，避免新旧样式混在一个目录
- 未下载完成的文件（`.qkdownloading`/`.part`/`.crdownload` 等）自动跳过，并在报告中说明原因

### 两种模式的共用能力

- 图形界面 + 命令行两种使用方式
- 批处理、递归搜索子目录
- 实时进度显示，台词模式显示「第 N/M 句」与预计剩余时间
- 处理过程中可随时取消
- 智能错误处理与超时控制，单句失败不中断整集

## 系统要求

- Python 3.12（建议；mediapipe 对 3.13 支持滞后，低于 3.9 无法使用其 Tasks API）
- FFmpeg / FFprobe（可用静态版解压使用，不强制加入 PATH）
- Windows / Linux / macOS

## 安装说明

1. 安装 Python 3.12（Windows 可选自定义安装目录，例如 `E:\Tools\Python312`，避免占满 C 盘）

2. 准备 FFmpeg。Windows 可直接下载静态版并解压，例如解压到 `E:\Tools\ffmpeg`（即存在 `E:\Tools\ffmpeg\bin\ffmpeg.exe`）。
   程序会按 `E:\Tools\ffmpeg\bin` → `C:\ffmpeg\bin` → `D:\ffmpeg\bin` → `C:\Program Files\ffmpeg\bin` → `D:\Program Files\ffmpeg\bin` → 系统 PATH 的顺序自动查找，因此**不一定要加入环境变量**。

   ```bash
   # Linux
   sudo apt-get install ffmpeg
   # macOS
   brew install ffmpeg
   ```

3. 安装第三方依赖：

   ```bash
   pip install -r requirements.txt
   ```

4. 确认人脸模型文件存在：`models/face_landmarker.task`（随项目提供，约 3.5 MB，本地推理用）。
   若该文件缺失，程序会自动回退到 OpenCV 自带的人脸级联检测，仍可出图，只是无法判定睁眼与嘴部状态，会在报告中标明当前使用的人像分析后端。

5. 中文台词依赖系统字体：优先 `C:\Windows\Fonts\msyhbd.ttc`（微软雅黑 Bold，与参考素材的字重一致），依次回退 `msyh.ttc`、`simhei.ttf`、`simsun.ttc`；全部缺失时回退到 Pillow 默认字体并给出提示（中文可能显示为方块）。

## 使用方法

### 图形界面

```bash
python main.py
```

界面顶部先选择截图模式，再按提示操作。

**台词智能截图模式：**

1. 点击「浏览...」选择**单集视频所在的文件夹**，例如 `...\Love in the big City\03`
2. 输出目录自动确定为该文件夹内的 `03-pc`（无需也无法手工设置）
3. 按需调整参数：字幕轨道（auto 为自动选择，优先简体中文）、每句候选帧数、只处理前几句（填 3 可快速试看效果）、是否在画面底部渲染台词、是否清空输出目录后重建
4. 点击「开始处理」，界面显示「第 N/M 句」进度；随时可点「取消」
5. 处理结束会弹出汇总，并在输出目录生成 `_index.csv` 与 `_report.txt`

**均匀截图模式（原有功能）：**

1. 选择包含视频文件的文件夹
2. 输出目录自动建议为父目录下的 `<文件夹名>_output`，也可手工指定
3. 设置每个视频截取的图片数量（默认 8 张）
4. 点击「开始处理」

### 命令行

不打开界面、逐集批量处理时使用命令行：

```bash
# 处理一集（输出到该集目录下的 03-pc）
python main.py --input "D:\...\Love in the big City\03"

# 先试跑前 3 句，确认效果后再跑整集
python main.py --input "D:\...\Love in the big City\03" --max-cues 3

# 从第 41 句开始跑到第 43 句
python main.py --input "D:\...\Love in the big City\03" --start-cue 41 --max-cues 3

# 指定字幕轨、提高候选帧数
python main.py --input "D:\...\Love in the big City\03" --subtitle-track 繁体中文 --candidate-max 15

# 不渲染台词文字、不跳过已存在图片（重新生成）
python main.py --input "D:\...\Love in the big City\03" --no-subtitle-text --no-resume

# 重建整集：先清空 03-pc 中的历史图片与旧索引，再全量重跑（换样式后推荐）
python main.py --input "D:\...\Love in the big City\03" --clean

# 半闭眼也重采样（更严格，耗时略增；默认只救「整句都闭眼」的句子）
python main.py --input "D:\...\Love in the big City\03" --clean --eye-refine half

# 均匀截图模式
python main.py --input "D:\...\某文件夹" --mode uniform --frames 20
```

命令行参数：

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `--input` | 输入目录（台词模式建议传单集目录） | 无，缺省则打开图形界面 |
| `--mode` | `dialogue`（台词智能截图）或 `uniform`（均匀截图） | `dialogue` |
| `--output` | 均匀截图模式的输出目录 | 输入目录同级 `<目录名>_output` |
| `--frames` | 均匀截图模式的截取数量 | `8` |
| `--subtitle-track` | 字幕轨选择，`auto` 为自动（优先简体中文），也可传轨名关键字 | `auto` |
| `--candidate-max` | 每句最多采样多少候选帧 | `10` |
| `--start-cue` | 从第几句开始处理 | `1` |
| `--max-cues` | 只处理前几句，`0` 表示全部 | `0` |
| `--no-subtitle-text` | 不在图片上渲染台词文字 | 关闭 |
| `--no-resume` | 不跳过已存在的图片 | 关闭 |
| `--clean` | 重建：先清空输出目录中该集的历史图片与旧索引再生成 | 关闭 |
| `--eye-refine` | 闭眼帧重采样口径：`closed`（整句都闭眼才救）/ `half`（半闭也救）/ `off`（关闭） | `closed` |

## 输出目录与文件命名

- **输出目录**：`视频所在目录名 + "-pc"`，位于该视频所在目录内。
  如 `...\Love in the big City\03\xx.mkv` → `...\Love in the big City\03\03-pc\`；
  `04` → `04\04-pc`，`05` → `05\05-pc`，依此类推。
- **图片命名**：`S01E03_0007_00-12-34.567.jpg`，即 `集号_四位句序_时间码.jpg`，按文件名排序即为台词顺序。
  集号取自视频文件名中的 `SxxExx`；若文件名没有该信息，则回退使用视频文件主名。
- **图片内容**：画面底部为白色粗体台词 + 黑色描边（无底色，最多 3 行，字号随行数自适应，不遮挡面部）。
- **`_index.csv`**：台词索引表（句序、起止时间码、时长、台词、文件名、画面时间码、综合得分、清晰度、运动惩罚、人脸数、**眼睛状态**（睁开/半闭/闭合，无人像留空）、嘴部是否自然、说话状态、构图分、时序分、镜头组、画面类型、是否降级）。采用合并写入，抽样试跑或断点续跑都不会写残整集索引；旧索引里的「是/否」眼睛列会在重跑（`--clean`）后换成三态文案。
- **`_report.txt`**：处理报告（字幕轨、人像分析后端、样式基线来源、总句数、成功/降级/跳过/失败数量、耗时、完整性校验结果、**逐集验收结论**、失败明细）。其中「逐集验收」小节会自动给出三量核对与「通过 / 需人工复核」的判定，命令行汇总中也会逐集打印「验收结论」。

### 关于「降级」

以下情况会正常出图，但索引表与报告中标记为降级，属于预期行为而非错误：

- 画面中检不到人脸（空镜、背影、远景、字幕卡）
- 画面为纯色/全黑/大虚化等平坦画面（例如只剩底部台词的过场）

## 逐集验收建议

1. 先用 `--max-cues 3` 试跑，打开生成的图片确认画面清晰、**人物睁着眼（不是闭眼/半闭眼/眨眼瞬间）**、说话自然、台词位置与样式与参考素材一致；试跑时报告结论会写「抽样试跑」，属正常
2. 确认无误后再跑整集（不加 `--max-cues`；换过样式或旧图样式不一致时加 `--clean`）
3. 处理完成后先看 `_report.txt`：「处理失败」应为 0、「完整性校验 → 发现缺失」应为 0、「逐集验收 → 结论」应为「通过」；再看「人像与眼睛」小节判断闭眼/半闭是否偏多
4. 再翻看 `_index.csv` 中「眼睛状态 = 半闭 / 闭合」、标记为降级、说话状态为「闭嘴 / 张口过大」的条目是否符合预期；若半闭偏多，可提高 `--candidate-max`（例如 15）后重跑该集
5. 未下载完成的文件会被自动跳过，报告中会列出文件名，下载完整后重新运行即可（已生成的图片会自动跳过）

### 交给 Agent 时必带的一句要求

除了跑通流程，还要让 Agent 理解画面语义，否则只会机械截取「有字幕的那一帧」。把下面要求一并交代（完整模板见使用指南第 7.4 节）：

```text
在执行视频截图时，需要深度理解视频中具体场景和台词的核心表达意图，
不仅截取直接出现台词字幕的画面，也要截取作为前文台词或情节延伸的关键画面。
例如第四集中，高煐妈妈在病床上让高煐把旁边抽屉里黄色的东西拿给她，
之后画面停留在高煐之前与卢英洙万圣节在夜店的合照上——
此类未直接出现当前台词、但承载前文情感或剧情延续的画面，
也应按其场景内涵识别并输出截图到对应文件夹中。
```

## 支持的视频格式

- MP4 (.mp4)、AVI (.avi)、MKV (.mkv)、MOV (.mov)、WMV (.wmv)、FLV (.flv)
- WebM (.webm)、M4V (.m4v)、MPG/MPEG (.mpg, .mpeg)、3GP (.3gp)

## 注意事项

- 台词模式要求视频带**文本型内嵌字幕轨**（SRT/ASS 等）；只有图形字幕（PGS/VobSub）或无字幕轨的视频无法提取台词，程序会明确报错说明原因
- 视频画面中直接烧入的字幕（硬字幕）无需也无法通过字幕轨获取，本工具不为这种情况做 OCR
- 确保有足够的磁盘空间存储截图
- 单集 1080p 处理耗时通常几分钟（约 390 句的实测约 5.7 分钟），主要消耗在视频解码与逐帧人脸推理
- 如果视频文件损坏或格式不支持，程序会跳过该文件并继续处理其他文件
- 处理大量视频建议逐集进行，便于逐集核对质量

## 台词样式基线

图片上的台词样式不是写死的，而是从参考素材统计出来的，存放在 `style_profile.json`：

- 测量内容：台词高度 / 画面高度、描边宽度 / 台词高度、台词底部到画面底边的距离、行数与行距倍数
- 渲染时按当前视频的实际分辨率换算成具体像素（字号、描边宽度、贴底距离），因此 1080p 与 720p 出来的是同一套视觉比例
- 样式基线文件缺失或损坏时，自动回退到 `config.py` 中的内置默认值，不影响出图，报告中会写明当前使用的来源

重新统计样式基线（换了参考素材时使用）：

```bash
# 统计全部素材组并写入 style_profile.json
python tools/analyze_reference.py

# 指定素材目录、只看某一组、或只打印不写文件
python tools/analyze_reference.py --reference "D:\...\素材3.0-3.2图片"
python tools/analyze_reference.py --group 素材3.0 --limit 60 --print-only
```

## 错误处理

- 程序会自动跳过无法处理的视频文件
- 单句台词处理失败不会中断整集，失败原因逐条写入 `_report.txt`
- 超出超时限制的 ffmpeg 调用会被终止并记录，不影响后续台词
- 所有错误都会在状态栏或命令行输出中显示相关信息
