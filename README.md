# 本地视频自动化截图工具（Video Pics Cut）

**一句话定位**：把一集带中文字幕的视频交给它，它会自动帮你「**每有一句台词，就截一张图**」，
把这句话以统一的样式印在画面底部，并按顺序命名保存好。

- 工具本体：`D:\03_Knowledge\intimate\Video Pics Cut`
- 剧集素材：`D:\03_Knowledge\intimate\Love in the big City`（每集一个文件夹）

> 换机器 / 换用户时，只需替换这两个路径与 Python / FFmpeg 的实际安装路径，其余规则不用改。

---

## 1. 这个工具帮你做什么

假设你要整理一部剧的资料，需要「每到一句台词，就留一张画面」。手动做的痛点很现实：

| 手动做 | 实际结果 |
| --- | --- |
| 一集几百句台词，一句句拖进度条截图 | 做不完，一部剧可能要十几个小时 |
| 随手暂停就截 | 经常截到眨眼、张嘴、糊帧 |
| 画面和台词对不上 | 回头看不出这张图对应哪句话 |
| 不同字幕格式截的图 | 每集的字号、位置、底色可能不一样，没法直接统一进行排版 |

这个工具把上面的活全自动做掉：

1. **读字幕**：从视频自带的软字幕中取出每句台词的开始/结束时间（不靠识别、没有错字）
2. **抓画面**：在每句台词的时间段里抓好几张候选画面（默认 5~10 张）
3. **挑最好的一张**：自动比清晰度、人物神态、画面构图，挑出最自然的一张
4. **印台词**：把该句台词以「白字 + 黑边、水平居中、贴近画面底部」的样式印上去
5. **按顺序存好**：命名成 `集号_第几句_时间码.jpg`，并生成一张索引表和一个处理报告

**适用场景**：整理剧集/影片资料、做图文回顾、给 AI 助手提供逐句配图素材。支持两种模式：

- **台词智能截图**（默认）：如上所述，逐句选优出图。
- **均匀截图**（原有功能）：在视频时长内均匀取帧，批量输出。

**重点（眼睛比嘴巴更重要）**：挑画面时它会**优先看人物眼睛**——
眼睛得是睁开的、两只眼开合差不多（不是一只睁一只闭），其次才看嘴巴是不是正在说话的自然口型。
所以它既避开「闭眼、半闭眼、眨眼瞬间」，也避开「张着血盆大口」的怪表情。

## 2. 主要功能特点

### 台词智能截图

- 自动识别视频中的中文字幕轨（优先「简体中文」），按字幕时间轴精确定位每句台词，无 OCR、无识别误差
- 每句台词在其时间区间内采样多张候选画面（默认 5~10 张，密度 3 帧/秒），挑出最优的一张
- 评分综合：画面清晰度、运动幅度、人像自然度（**眼睛状态**、说话状态、人脸面积）
- **以眼睛为主的神态判定**：
  - 左右眼分别算开合比（EAR），做「绝对标定 + 句内相对标定 + 双眼是否对称睁开」三重比较
  - 闭眼重罚、半闭眼轻罚、单眼微闭（眨眼瞬间）轻罚；嘴部只保留「张口过大」一层惩罚，权重低于眼睛
  - 选优时先取本句最高分，再在「最高分 - 0.15」的优选窗口内优先挑选**睁着眼**的一帧，兼顾画质与神态
  - 出图帧的眼睛状态（睁开 / 半闭 / 闭合 / 无人像）写入索引表并计入报告统计
- 情境匹配加分：构图更居中、更贴近句子中点、与句子中点同一镜头的候选帧优先，减少「画面与台词对不上」
- **闭眼帧重采样**：整句候选都没睁眼时，自动把该句候选帧数与采样密度临时提高（默认 30 帧 / 6 帧每秒）再挑一次，确认「眼睛状态确实变好」才替换图片
- 无人像的空镜、背影、远景、字幕卡（哪怕全黑只剩底部台词）同样正常出图，仅在索引表中标记为降级
- **剧情延续帧自动补截**：从完整字幕时间轴系统化枚举全部无台词空窗（相邻台词间隔 ≥ 6 秒，含片头/片尾），空窗内采样候选帧后按「剧情帧口径」选优（不施加闭眼/嘴部惩罚——哭戏闭眼、沉默反应是合法剧情帧，只看清晰度、运动、构图与人像面积），同一空窗按**镜头分组去重**（每个镜头只出一张代表帧），每窗至多 3 张，杜绝近重复；句序记为「前接句序号 4 位 + 子后缀 a/b/c」（如 `0004a`、`0298b`）写入同一张 `_index.csv`，按文件名字母序天然插在对应台词帧之间，报告列出全部空窗明细供人工复核；已补截或已人工淘汰的空窗重跑自动跳过（索引保留台账），不会重复补截
- 台词以**白色粗体 + 黑色描边（无底色）**贴在画面底部，样式取自参考素材统计出的基线 `style_profile.json`
- 有序命名（含集号、句序、时间码），按时间顺序排列
- 每集输出 `_index.csv`（台词索引表）与 `_report.txt`（处理报告）
- 收尾做完整性校验：字幕句数 / 目录图片数 / 索引行数三方对齐，缺图的句子自动补跑
- 断点续跑：已生成的图片自动跳过，中断后重跑不重复劳动
- 重建模式（`--clean` 或界面勾选）：先清空该集历史图片与旧索引再生成，避免新旧样式混装
- 未下载完成的文件（`.qkdownloading`/`.part`/`.crdownload` 等）自动跳过，并在报告中说明原因

### 两种模式的共用能力

- 图形界面 + 命令行两种使用方式
- 批处理、递归搜索子目录
- 实时进度显示，台词模式显示「第 N/M 句」与预计剩余时间
- 处理过程中可随时取消
- 智能错误处理与超时控制，单句失败不中断整集

## 3. 它做不到什么（已知限制）

| 它做不到 | 原因 | 你该怎么办 |
| --- | --- | --- |
| 视频没有字幕时无法出图 | 台词来自视频自带字幕，不是听声音 | 换带中文字幕的片源，或先加字幕 |
| 画面里「烧死」的字幕（硬字幕）读不到 | 硬字幕是图像的一部分，需要 OCR，本工具不做 | 换软字幕片源 |
| 只有图形字幕（PGS/VobSub）的片源读不到 | 这类字幕不是文字格式 | 换软字幕片源 |
| 无人物的空镜、物品特写没有人脸判断 | 画面里没有人，就没有眼睛/嘴巴可判断 | 正常现象，报告里记为「无人像」，图照样出 |
| 不能保证 100% 每张图都完美 | 它是「挑相对最好的一张」，不是人工精修 | 报告里会给出统计，按第 10 节抽查即可 |
| 剧情延续帧的「语义判断」工具不做 | 工具只负责系统化枚举空窗、选优、去重、落盘与台账；画面是否承载剧情需人工/AI 复核 | 按第 10.4 节复核 0004a/b/c 剧情帧图片决定去留即可 |
| PNG 输出需改源码 | 默认固定 JPG（质量 95） | 把 `video_tool/config.py` 的 `IMAGE_FORMAT = "jpg"` 改成 `"png"`，改后对该集 `--clean` 重建 |

**联网与隐私的准确说法**：

- **处理视频这一步，永远在本机完成**——字幕来自视频自带字幕轨，画面评分与人脸分析都在本机 CPU 上推理，视频与图片不会被上传
- **联网只发生在**：① 首次安装（下载 Python / FFmpeg / 依赖包）；② 使用 AI 助手（CodeBuddy 等）下达指令与查看结果；③ 万一需要重新下载人脸模型文件
- 若只用命令行或 `.bat` 脚本运行，**日常使用可以完全不联网**（第 8.3 节会教你）


## 6. 输出规则与文件命名

- **输出目录**：视频所在目录名 + `-pc`。如 `...\03\xx.mkv` → `...\03\03-pc\`
- **图片内容**：原片画面 + 该句台词（白色粗体 + 黑色描边、无底框、水平居中、贴近画面底部、最多 3 行，字号随行数自适应，不遮挡面部）；原片完整画幅输出（不裁剪、不缩放、不加边框、不加任何水印）
- **命名规则**（三要素：`集数` → `时间码` → `场景描述`，两种形态同一集内必须统一）：
  - **推荐形态（工具原生命名 + 描述后缀，可断点续跑）**：
    `S01E04_0131_00-31-12.500_高煐翻看夜店合照.jpg`
    （集数 → 四位句序 → 时间码 → 场景描述；句序段仅为排序与续跑服务）
  - **严格形态（去掉句序段）**：`S01E04_00-31-12.500_高煐翻看夜店合照.jpg`
    ⚠️ 会破坏断点续跑（工具靠 `<集号>_<四位句序>_` 前缀判断已生成），必须在整集跑完确认无误后再批量改名；日后重跑该集必须加 `--clean`
  - `集数` 取自视频文件名中的 `SxxExx`，没有时回退用视频主名；`时间码` 格式 `HH-MM-SS.mmm`，可被 `ffmpeg -ss` 直接复用；`场景描述` 为中文短语 8~20 字，只允许中文、字母、数字、`-`，不得有空格与 `\ / : * ? " < > |`
- **无台词剧情延续帧**：由工具自动补截，命名格式「**前接句序号 4 位 + 子后缀 a/b/c**」（如 `S01E04_0004a_00-31-12.500.jpg`、`S01E04_0298c_00-46-46.186.jpg`）。片头空窗（无前接）用占位 `0000a/b/c`，片尾取末句 `0298a/b/c`。**字符码序 `0..9 < a..z`** 保证按文件名字母序天然按叙事顺序穿插在台词帧之间，不需要单独目录也不打乱阅读。每空窗至多 3 张（`a/b/c`）。补截后如需加场景描述后缀，遵守与台词帧一致的两种形态规则
- **`_index.csv`**（utf-8-sig，Excel 可直接打开）：句序、起止时间码、时长、台词、文件名、画面时间码、综合得分、清晰度、运动惩罚、人脸数、**眼睛状态**（睁开/半闭/闭合，无人像留空）、嘴部是否自然、说话状态、构图分、时序分、镜头组、画面类型、是否降级。采用合并写入，抽样试跑或断点续跑都不会写残整集索引。**剧情延续帧行的句序为「4 位数字 + 小写字母」**（`0004a`、`0298b`），起止时间码记录其所属无台词空窗的范围，台词列为空窗描述（前接/后接哪句台词）——该行同时充当「此空窗已处理」的台账
- **`_report.txt`**：字幕轨、人像分析后端、样式基线来源、总句数、成功/降级/跳过/失败数量、耗时、完整性校验结果、**剧情延续帧小节**（空窗总数、补截张数、逐空窗明细与复核建议）、**逐集验收结论**、失败明细
- 每个 `XX-pc` 目录内应有且仅有三类文件：`*.jpg`、`_index.csv`、`_report.txt`；临时抽帧目录与运行日志不要留在交付目录里

**关于「降级」**：画面检不到人脸（空镜、背影、远景、字幕卡）或画面为纯色/全黑/大虚化等平坦画面时，图片照常输出，仅在索引表与报告中标记为降级，属预期行为而非错误（本剧集约 4~5 成）。

## 7. 使用方式一：图形界面

```bash
python main.py
```

界面顶部先选择截图模式，再按提示操作。

**台词智能截图模式：**

1. 点击「浏览...」选择**单集视频所在的文件夹**，例如 `...\Love in the big City\03`
2. 输出目录自动确定为该文件夹内的 `03-pc`（无需也无法手工设置）
3. 按需调整参数：字幕轨道（auto 为自动选择，优先简体中文）、每句候选帧数、只处理前几句（填 3 可快速试看效果）、是否在画面底部渲染台词、是否清空输出目录后重建
4. 点击「开始处理」，界面显示「第 N/M 句」进度；随时可点「取消」
5. 处理结束会弹出汇总，并在输出目录生成 `_index.csv` 与 `_report.txt`

**均匀截图模式：**

1. 选择包含视频文件的文件夹
2. 输出目录自动建议为父目录下的 `<文件夹名>_output`，也可手工指定
3. 设置每个视频截取的图片数量（默认 8 张）
4. 点击「开始处理」

## 8. 使用方式二：命令行与离线脚本

### 8.1 命令行用法

```bash
# 处理一集（输出到该集目录下的 03-pc）——路径含空格必须整段加双引号！
python main.py --input "D:\...\Love in the big City\03"

# 先试跑前 3 句，确认效果后再跑整集
python main.py --input "D:\...\Love in the big City\03" --max-cues 3

# 从第 41 句开始跑到第 43 句
python main.py --input "D:\...\Love in the big City\03" --start-cue 41 --max-cues 3

# 指定字幕轨、提高候选帧数
python main.py --input "D:\...\Love in the big City\03" --subtitle-track 繁体中文 --candidate-max 15

# 不渲染台词文字、不跳过已存在图片（重新生成）
python main.py --input "D:\...\Love in the big City\03" --no-subtitle-text --no-resume

# 重建整集：先清空 03-pc 中的历史图片与旧索引再全量重跑（换样式后推荐）
python main.py --input "D:\...\Love in the big City\03" --clean

# 半闭眼也重采样（更严格，耗时略增；默认只救「整句都闭眼」的句子）
python main.py --input "D:\...\Love in the big City\03" --clean --eye-refine half

# 不补截剧情延续帧，或调整空窗阈值与每空窗上限
python main.py --input "D:\...\Love in the big City\03" --no-story-gaps
python main.py --input "D:\...\Love in the big City\03" --story-gap-min 8 --story-gap-max-per 2

# 均匀截图模式
python main.py --input "D:\...\某文件夹" --mode uniform --frames 20
```

**完整参数表**：

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `--input "路径"` | 输入目录（台词模式传单集目录，**含空格必须加引号**） | 无，缺省则打开图形界面 |
| `--mode` | `dialogue`（台词智能截图）或 `uniform`（均匀截图） | `dialogue` |
| `--output` | 均匀截图模式的输出目录 | 输入目录同级 `<目录名>_output` |
| `--frames` | 均匀截图模式的截取数量 | `8` |
| `--subtitle-track` | 字幕轨选择，`auto` 为自动（优先简体中文），也可传轨名关键字 | `auto` |
| `--candidate-max` | 每句最多采样多少候选帧（半闭眼偏多可提到 15） | `10` |
| `--start-cue` | 从第几句开始处理 | `1` |
| `--max-cues` | 只处理前几句，`0` 表示全部 | `0` |
| `--no-subtitle-text` | 不在图片上渲染台词文字 | 关闭 |
| `--no-resume` | 不跳过已存在的图片（重新生成） | 关闭 |
| `--clean` | 重建：先清空该集历史图片与旧索引再生成 | 关闭 |
| `--eye-refine` | 闭眼帧重采样口径：`closed`（整句都闭眼才救）/ `half`（半闭也救）/ `off`（关闭） | `closed` |
| `--no-story-gaps` | 不补截剧情延续帧（台词之间的无台词空窗） | 关闭（默认补截） |
| `--story-gap-min` | 无台词空窗的最短间隔秒数（含片头/片尾） | `6.0` |
| `--story-gap-max-per` | 镜头去重后每个空窗最多补截几张 | `3` |

**长时间任务必须后台运行 + 日志落盘**（一集约 200~350 秒，前台跑会一直卡住等待）：

```bat

set PYTHONIOENCODING=utf-8
"E:\Tools\Python312\python.exe" -u main.py --input "D:\03_Knowledge\intimate\Love in the big City\08" --clean > "_run08.out.log" 2> "_run08.err.log"
```

> **踩过的坑**：素材路径含空格（`Love in the big City`），`--input` 的值**必须整段加双引号**。
> 曾因未加引号报错 `main.py: error: unrecognized arguments: in the big City\08`，第 08 集因此中断在第 54 句。

### 8.2 PowerShell 差异

- 行首是带引号的 exe 路径时，前面加 `& `（例如 `& "E:\Tools\Python312\python.exe" main.py --help`）

## 9. 使用方式三：让 AI 助手指挥（首次跑通推荐）

第一次用、想省事，推荐用 AI 助手（CodeBuddy / Codex / Cursor / VSCode 内 AI 等）指挥：
**AI 助手 = 执行人**（跑工具、抽帧、自查、汇报）；**你 = 验收人**（逐集人工确认）。

关键只有一条：要能把本工具目录打开成「工作区」，AI 才能读到代码、执行命令。

整体路线：**先用「有人帮忙」的方式跑通 → 再固化成离线脚本 →（可选）以后再打包成 exe**。

### 9.1 基本流程（一集五步）

1. **环境自检**：让 AI 跑第 4.3 节的自检命令，确认依赖齐备、`--help` 能打印参数说明
2. **先只跑 3 句看效果**（不要一上来跑整集）：

   ```text

   输入目录 D:\03_Knowledge\intimate\Love in the big City\05，
   先只处理前 3 句让我看效果，跑完把生成的图片路径和 _report.txt 的内容告诉我。
   ```

   打开图片检查：① 台词位置、字号是否顺眼；② 人物是不是睁着眼；③ 台词和画面是否说得通。
   （只跑 3 句时报告结论会写「抽样试跑」，属正常。）确认后删掉这 3 张试跑图再跑整集。

3. **跑整集**（换过样式加 `--clean`），并要 AI 报回成功/失败/缺失/眼睛状态统计
4. **AI 复核剧情延续帧**（工具已在整集跑完时自动补截 `0004a/b/c` 等剧情帧图片，见第 10.4 节）
5. **按汇报验收，停下等确认**；一集一集来，严禁自动连跑下一集

### 9.2 交给 AI 时必带的剧情理解要求

只按台词截，会漏掉「没有台词但承载剧情」的画面。把下面这段话一起交代给 AI：

```text
在执行视频截图时，需要深度理解视频中具体场景和台词的核心表达意图，
不仅截取直接出现台词字幕的画面，也要截取作为前文台词或情节延伸的关键画面。

例如第四集中，高煐妈妈在病床上让高煐把旁边抽屉里黄色的东西拿给她，
之后画面停留在高煐之前与卢英洙万圣节在夜店的合照上——
此类未直接出现当前台词、但承载前文情感或剧情延续的画面，
也应按其场景内涵识别并输出截图到对应文件夹中。
```

它会带来两条产出：① 工具自动出的图（每句台词一张，基础盘）；② 剧情延续帧（工具自动补截的 `0004a/b/c` 等剧情帧——合影、物件特写、空镜、人物反应镜头等「没台词但重要」的候选画面，AI 只需逐张复核去留，不必再手工抽帧找画面）。

## 10. 跑完怎么验收

### 10.1 三条对照法

打开 `xx-pc` 文件夹，看三样：

**① 看 `_report.txt`（成绩单）**——必须满足：

- `成功出图` = `台词总句数`
- `处理失败` = 0
- `完整性校验 → 发现缺失` = 0
- `逐集验收 → 结论` 为「通过」（正式整集跑才这么写；「基本通过（…建议目检）」多因剧情闭眼动作，不等于失败，但须列出说明）

**② 看 `_index.csv`（台账）**——台词行数（不含表头与剧情帧行）应与台词图片张数一致；剧情帧行（`0004a` 等格式）的「文件名」列为空表示该空窗的候选图已被人工淘汰（台账行，属正常）；

- **眼睛状态**列：`睁开` 是理想结果，`半闭` 有点可惜，`闭合` 说明整句没挑到更好的帧（越少越好），空着表示画面里没有人
- **说话状态**列：`正在说话` / `闭嘴` / `张口过大`
- **是否降级**列：`是` 表示这句画面里没人或画面很空，属正常保留，不是失败

**③ 抽 2 张图眼看一遍**——抽一张「有人脸、眼睛状态=睁开」的确认神态自然、台词清楚；抽一张「无人像」的确认空镜/字幕卡正常。

### 10.2 交付前核对清单（逐条打勾才能汇报）

- [ ] 2. 命名合规：抽查 3 个文件名满足 `集数_时间码_场景描述`，字符合法、无空格、同集风格统一
- [ ] 3. 样式一致：抽查 2~3 张，白字粗体 + 黑描边、水平居中、贴底、最多 3 行；无额外水印、无半透明黑底
- [ ] 4. 剧情延续帧已复核：工具自动补截的 `0004a` 等剧情帧图片已逐张查看，与剧情无关的已删除（`_audit.csv` 中的「建议删除」已通过 `apply_audit_deletions.py` 处理），保留清单已列出
- [ ] 5. 画质与人物状态：有人脸且眼睛睁开的图清晰不糊；无人像空镜/字幕卡同样清晰保留；闭眼帧已列为遗留问题

### 10.4 无台词「剧情延续帧」的复核与补截（交付必做项）

工具在整集跑完时会**自动补截**剧情延续帧：从完整字幕时间轴枚举全部无台词空窗（相邻台词间隔 ≥ 6 秒，含片头/片尾），空窗内按镜头去重后挑画质最优的代表画面，每窗至多 3 张；命名格式为「**前接句序号 4 位 + 子后缀 a/b/c**」（如 `0004a`、`0298b`），写入 `_index.csv`；字符码序 `0..9 < a..z` 保证按文件名字母序天然按叙事顺序穿插在台词帧之间。`_report.txt` 的「剧情延续帧」小节列出全部空窗明细（时间范围、是否补截、跳过原因）。

工具同时把每张剧情帧的客观质量画像写到 `_audit.csv`（Laplacian 清晰度、平均亮度、镜头组、前/后接台词、命中 flag、推荐结论），AI/人工可以先扫审计再决定删留。交付前必做项因此从「人工找画面」变成「看现成候选图 + 审计报告做语义复核」：

1. **读报告核对空窗覆盖**：`_report.txt` 的空窗明细逐条过一遍——每个空窗都应有「补截 N 张」或明确的跳过原因（空窗过短 / 全为黑场字幕卡），不应有被遗漏的静默区间
2. **跑质量审计拿到 `_audit.csv`**（**新增工具**）：

   ```bash
   python tools/audit_story_quality.py --input "D:\…\Love in the big City\08"
   ```

   输出列：推荐（建议删除/复核/保留）、句序、文件名、空窗起止、画面时间码、清晰度、画面类型、人脸数、眼睛状态、前接台词、后接台词、命中 flag。规则：
   - **硬 flag**（计入删除）：模糊(Lap<30) / 极暗(L<8) / 黑场卡 / 同空窗近重复(<1.5s)
   - **软 flag**（仅记录）：无脸 / 镜头模糊 / 贴近空窗边缘 / 空窗首张
   - 推荐：空窗首张→保留；硬 flag ≥ 2→建议删除；硬 flag = 1→复核；否则→保留
3. **逐张查看 `0004a/b/c` 剧情帧图片**（AI 可直接读取图片）：判断是否承载前文情感 / 回忆 / 信物 / 剧情延续
4. **批量删除审计建议项**（**新增工具**）：

   ```bash
   python tools/apply_audit_deletions.py --input "D:\…\Love in the big City\08" --recommend 建议删除
   ```

   删除图片文件 + `_index.csv` 中对应行的「文件名」清空（**保留台账行**），重跑不会把人工淘汰过的画面再补一遍。`--recommend 复核` 可选，会更激进；`--dry-run` 只打印计划
5. **需要重新补截某空窗时**：删掉 `_index.csv` 中对应 `0004a` 那一行后重跑该集（断点续跑，台词图全部跳过，只重补该空窗）；如需给保留的剧情帧加场景描述后缀，整集确认后统一批量改名
6. **记录到汇报**：清单格式 = 时间码 + 画面内容 + 为什么必须截

**必须保留的典型承载帧类型**：

| 类型 | 例子 | 是否必留 |
| --- | --- | --- |
| 回忆/信物特写 | 万圣节夜店合照、抽屉里的黄色物件、旧照片、票据 | **必留** |
| 人物反应镜头 | 台词后人物沉默、落泪、回望、握拳、长吸气 | **必留** |
| 场景空镜 | 空荡的房间、雨夜背影、渐隐黑场前的最后一帧 | 视剧情承载而定 |
| 纯黑过场 / 字幕卡 | 仅底部有文字的过场 | 一般不留（工具已自动跳过大部分） |

> 工具的选优口径与台词帧不同：不施加闭眼/嘴部惩罚（哭戏闭眼、沉默反应是合法剧情帧），纯黑/纯色过场自动跳过。语义判断（这张画面是否承载剧情）仍由人工/AI 完成。**已用过的客观质量审计工具只是辅助，AI/人工对剧情承接度的判断才是最终依据**。

**08 集特殊说明**：如果你之前是用旧版（`X01/X02/…` 命名）跑出的 08 集，文件名前缀 `S01E08_X##_` 不会自动改写，需要先跑一次迁移工具：

```bash
python tools/migrate_story_naming.py --input "D:\…\Love in the big City\08" --dry-run   # 先看计划
python tools/migrate_story_naming.py --input "D:\…\Love in the big City\08"            # 实际改名
```

迁移只重命名图片 + 改 `_index.csv` 句序/文件名/排序，**不重抽帧**。1-7 集不需要这个步骤。

## 11. 常见问题（对着现象找）

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `error: unrecognized arguments: in the big City\08` | `--input` 路径未加引号，被空格截断 | 给路径加双引号后重跑（断点续跑，不会重做已完成部分） |
| 报错「找不到字幕 / 没有台词」 | 片源没有文字型软字幕（只有硬字幕或图形字幕） | 换片源；本工具不做 OCR |
| 报告写「跳过未下载完成」 | 目录里有 `.qkdownloading` / `.part` 文件 | 等下载完整再跑一次 |
| 图片数比台词数少 | 极少数句子处理失败 | 直接再跑一次，工具会自动补跑缺的句子 |
| 换过台词样式后，新旧图片混在一起 | 老图片还在目录里 | 加 `--clean` 重跑该集（会先清空这一集的图） |
| 中文显示成方块 | 系统缺中文字体 | 装微软雅黑，或把 `msyh.ttc` 放到 `C:\Windows\Fonts` |
| 看不到进度 | 后台跑的，看不到实时进度 | 看输出目录里图片数量在不在增加；或看 `_run*.log` |
| 满屏 WARNING / 黄字 | 人脸库的正常噪音 | 忽略，只看报告里的汇总 |
| 想确认哪几句「眼睛是闭的」 | 需要人工复查 | 在 `_index.csv` 里筛「眼睛状态 = 闭合 / 半闭」，对着图看 |
| 重跑后剧情帧又出现了？ | 该空窗在 `_index.csv` 中没有台账行（例如曾用旧版 `X##` 命名工具处理） | 正常现象：08 集先跑 `tools/migrate_story_naming.py` 迁移到新命名后再继续；新格式下会自动记账 |
| X 图片删了但 CSV 里还有一行 | 台账行：防止人工淘汰过的空窗被重复补截 | 留着即可；想重新补截该空窗就删掉那一行再重跑 |
| 半闭眼的图偏多 | 候选帧抓得太少 | 加 `--candidate-max 15` 或 `--eye-refine half` 重跑该集 |
| 报告里仍有「眼睛闭合」 | 整句候选都没睁眼，重采样也没救回来 | 属剧情动作（低头、闭眼喝水等）；想更严格可加 `--eye-refine half` 重跑 |
| 视频文件损坏或格式不支持 | — | 程序会跳过该文件并继续处理其他文件 |

**红线（禁止事项）**：

1. 不得联网处理素材：不使用任何在线 API / 云服务 / 在线 OCR / 在线翻译（AI 助手自身除外）
2. 不得修改素材目录：`素材3.0-3.2图片` 只读；不得增删改任何原始素材与视频文件
3. 不得跨集并行：未经确认，不得同时跑两集，也不得提前跑下一集
4. 不得跳过自检：三量对齐与抽样目视未通过前，不得汇报「已完成」
5. 不得默认丢图：任何一句台词缺配图都必须先补跑，补跑仍失败要在报告中显式说明
6. 不得残留旧图：变更样式 / 格式后必须 `--clean` 重建
7. 不得删除已验收产物：已确认通过的集数目录，只允许追加（补截图），不得整体清空或删除
8. 不得隐藏问题：闭眼帧、失败句、未下载完成的文件、分辨率不符等，一律如实写进汇报
9. 不得漏掉无台词承载帧：第 10.4 节的复核是交付必做项，不是可选项；报告「剧情延续帧」小节中的每个空窗都必须逐条核对
10. 路径必须加引号：所有含空格路径在命令中必须整段加双引号

**其他注意事项**：

- 确保有足够的磁盘空间存储截图
- 单集 1080p 处理耗时通常几分钟（约 390 句的实测约 5.7 分钟），主要消耗在视频解码与逐帧人脸推理
- 处理大量视频建议逐集进行，便于逐集核对质量
- 若输入片源不是 1080p，须在汇报中说明实际分辨率，不得谎报

| 眼睛状态（睁开/半闭/闭合） | 画面里最主要人物的眼睛睁得怎么样；半闭包含「一只眼睁一只眼眯」 |
| 说话状态（正在说话/闭嘴/张口过大） | 主要人物嘴巴的开合情况，用来辅助判断神态 |
| 降级 | 这句话的画面里没人（空镜、背影、远景、字幕卡），图照出，只是标注一下 |
| 完整性校验 | 跑完后自动对账：台词句数、图片张数、台账行数是不是一样 |
| 闭眼重采样 | 整句候选都闭眼时，自动把这一句的候选画面多抓一倍多、再挑一次 |
| 断点续跑 | 已经生成过的图片自动跳过，中断了再跑不会重复做 |
| 重建（`--clean`） | 先清掉这一集的历史图片和旧台账，再从零跑一遍 |
| 剧情延续帧 | 没有台词、但承载前文情感或剧情延续的关键画面；工具按无台词空窗自动补截，命名形如「前接句序号 4 位 + 子后缀 a/b/c」（如 `0004a`），按文件名字母序穿插在对应台词帧之间，去留由人工复核 |
| 无台词空窗 | 相邻两句台词之间（含片头/片尾）间隔 ≥ 6 秒的静默区间 |
| 样式基线 | 从参考素材里统计出来的「台词该多大、多粗、离底边多远」的一组数值 |
| FFmpeg | 一个负责读视频、抽画面的免费小工具，程序在后台用它 |
| mediapipe 人脸模型 | 用来判断人脸、眼睛、嘴巴状态的本地小模型文件（约 3.5 MB） |

## 13. 台词样式基线

图片上的台词样式不是写死的，而是从参考素材统计出来的，存放在 `style_profile.json`：

- 基线来源素材：`Love in the big City\素材3.0-3.2图片`（人工精修过的参考图），共 3 组，命中 230 张样本
- 测量内容：台词高度 / 画面高度、描边宽度 / 台词高度、台词底部到画面底边的距离、行数与行距倍数
- 渲染时按当前视频的实际分辨率换算成具体像素，因此 1080p 与 720p 出来的是同一套视觉比例
- 基线文件缺失或损坏时，自动回退到 `config.py` 内置默认值，不影响出图，报告中会写明来源

重新统计样式基线（换了参考素材时使用）：

```bash
python tools/analyze_reference.py
python tools/analyze_reference.py --reference "D:\...\素材3.0-3.2图片"
python tools/analyze_reference.py --group 素材3.0 --limit 60 --print-only
```
